 === README.md ===
# tidewick

A small, dependency-free Python library and command-line tool that predicts tide heights for a handful of
fictional stations from harmonic constituents stored as JSON. It exists as example material: the stations,
the numbers and the project are made up.

## Quick start

```bash
python -m tidewick stations                 # list the stations in the data directory
python -m tidewick predict port-avery --hours 24
python -m tidewick predict cape-mallow --at 2026-03-01T06:00
```

Python 3.11 or later. No third-party packages, by policy (see CONTRIBUTING.md).

All times in and out of the tool are a station's local **standard** time, year-round; tidewick never applies
a daylight-saving shift (see `docs/ARCHITECTURE.md`). A printed tide table that follows the local civil clock
will run an hour ahead of tidewick's times while daylight saving is in effect.

## Layout

- `tidewick/`: the package. `predict.py` does the arithmetic, `stations.py` loads station files,
  `harmonics.py` holds the constituent speeds, `cli.py` is the command line, `config.py` finds the data.
- `data/`: `stations.json` and one constituents file per station.
- `tests/`: the unit tests. Run them with `make test`.
- `tools/`: `check_style.py` (the style rules `make check` enforces) and `make_fixtures.py` (writes a
  constituents file for a new station).
- `docs/`: `ARCHITECTURE.md` and the decision records under `docs/adr/`.

## Data directory

The tool reads station data from the directory named in `TIDEWICK_DATA_DIR`, or `./data` when that is not
set.

# Contributing to tidewick

- Python 3.11 is the floor. No third-party dependencies, in the package or the tests: the standard library only.
- Keep changes small: one concern per change, with a test.
- Commit messages use the conventional form: `feat(cli): ...`, `fix(predict): ...`, `docs: ...`.
- Run `make check` before you send a change. It runs the tests and `tools/check_style.py`, which enforces:
  lines of at most 100 characters, no `print()` in the package outside `cli.py`, and a module docstring in
  every file under `tidewick/`.
- Station ids are lowercase kebab-case (`port-avery`), and they are the file names under
  `data/constituents/`.
- Releases: update `CHANGELOG.md` (newest first, one "## x.y.z - YYYY-MM-DD" heading per release), set
  `__version__` in `tidewick/__init__.py`, and tag `vX.Y.Z`.
- `tidewick/legacy_parser.py` reads the retired 0.x text format. It is frozen: do not extend it, and do not
  make new code depend on it. It will be deleted once the last 0.x data files are converted.

 === docs/ARCHITECTURE.md ===
# Architecture

tidewick predicts a tide height h(t) at a station as

    h(t) = Z0 + sum over constituents of A_i * cos(speed_i * t_hours + phase_i)

where Z0 is the station's mean level, A_i and phase_i come from the station's constituents file, and speed_i
(degrees per hour) comes from `harmonics.SPEEDS`. t_hours is hours since the station's epoch,
2026-01-01T00:00 in the station's local standard time. Station files give times in local standard time all year:
there is no daylight-saving adjustment anywhere in the code, on purpose.

Modules:
- `config.py`: resolves the data directory (TIDEWICK_DATA_DIR, else ./data relative to the working directory).
- `stations.py`: loads and validates `stations.json` and `constituents/<id>.json`.
- `harmonics.py`: constituent names and speeds. Pure data plus one helper.
- `predict.py`: `height_at(station, when)` and `series(station, start, hours, step_minutes)`.
- `cli.py`: argument parsing and printing. The only module allowed to print.
- `legacy_parser.py`: reads the retired 0.x text format. Frozen; see CONTRIBUTING.md.

Decision records live in `docs/adr/`.

 === docs/adr/0002-json-files-not-sqlite.md ===
# 2. Station data as JSON files, not SQLite

Status: accepted (2025-12)

Each station is one small JSON file under `data/constituents/`, listed in `data/stations.json`. We
considered one SQLite file. JSON won because the files are reviewed in pull requests line by line, a station
is added by adding a file, and nothing in the tool needs queries across stations. If cross-station queries
ever matter, revisit this.

     1	"""The prediction arithmetic."""
     2	
     3	import math
     4	from datetime import datetime, timedelta
     5	
     6	from tidewick import harmonics
     7	from tidewick.stations import Station
     8	
     9	EPOCH = datetime(2026, 1, 1)  # local standard time at every station
    10	
    11	FEET_PER_METER = 3.28084
    12	
    13	MINUTES_PER_HOUR = 60
    14	SECONDS_PER_HOUR = 3600.0
    15	
    16	
    17	def to_units(meters: float, units: str) -> float:
    18	    """Convert a height in metres to the given unit ('m' or 'ft')."""
    19	    if units == "m":
    20	        return meters
    21	    if units == "ft":
    22	        return meters * FEET_PER_METER
    23	    raise ValueError(f"unknown units {units!r}; expected 'm' or 'ft'")
    24	
    25	
    26	def _hours_since_epoch(when: datetime) -> float:
    27	    """Hours elapsed since EPOCH, as a float; negative if `when` precedes it."""
    28	    return (when - EPOCH).total_seconds() / SECONDS_PER_HOUR
    29	
    30	
    31	def height_at(station: Station, when: datetime) -> float:
    32	    """Predicted height in metres at a local standard time."""
    33	    t_hours = _hours_since_epoch(when)
    34	    total = station.mean_level_m
    35	    for name, amplitude, phase_deg in station.constituents:
    36	        angle = math.radians(harmonics.speed(name) * t_hours + phase_deg)
    37	        total += amplitude * math.cos(angle)
    38	    return total
    39	
    40	
    41	def series(
    42	    station: Station, start: datetime, hours: int, step_minutes: int = 60
    43	) -> list[tuple[datetime, float]]:
    44	    """(time, height) pairs from start for the given number of hours."""
    45	    if hours <= 0 or step_minutes <= 0:
    46	        raise ValueError("hours and step_minutes must be positive")
    47	    step_count = int(hours * MINUTES_PER_HOUR / step_minutes) + 1
    48	    times = (start + timedelta(minutes=i * step_minutes) for i in range(step_count))
    49	    return [(when, height_at(station, when)) for when in times]

## Docs that no longer match the code

1. **Data directory default is stale in two places.** README's "Data directory" section says it's `TIDEWICK_DATA_DIR`, "or `./data` when that is not set," and `ARCHITECTURE.md` repeats "else ./data relative to the working directory." But `config.py` (fixed in the 0.4.0 changelog entry) actually defaults to the `data/` directory *next to the installed package*, independent of cwd. The changelog got updated, the two docs didn't.
2. **`legacy_parser.py`'s stated purpose is already obsolete.** `CONTRIBUTING.md` and `ARCHITECTURE.md` describe it as "frozen... kept for conversion" until "the last 0.x data files are converted." There are no 0.x text files anywhere in the repo and nothing calls `parse_legacy` — the conversion this module exists for is already finished, so the rationale in the docs no longer describes reality.

## Prioritized next steps

1. **Make the CLI fail gracefully instead of dumping tracebacks.** Bad station id, a malformed `--at` value, or `--hours`/`--step-minutes` ≤ 0 all currently raise uncaught `ValueError`s straight through `python -m tidewick`, which is the worst experience for the one module whose job is user-facing output, and none of these paths are tested.
2. **Reconcile README/ARCHITECTURE with the real `config.py` behavior** (item 1 above) — leaving this stale actively misleads anyone deploying the tool or trying to override `TIDEWICK_DATA_DIR`.
3. **Add tests for `config.data_dir()`** (cwd independence, `TIDEWICK_DATA_DIR` override) since it currently has zero coverage despite being the exact logic that was bug-fixed in 0.4.0, so a regression would go unnoticed.
4. **Resolve `legacy_parser.py`'s status**: delete it now that no 0.x data remains and nothing references it, or if it must stay a bit longer, give it a test and update the docs to say what's actually still pending — right now it's untested, uncalled, dead code with an inaccurate rationale attached.
5. **Decide what `Station.utc_offset_hours` is for.** It's parsed and validated from `stations.json` for every station but never consumed by `predict.py` or shown by `cli.py`; either use it (e.g., display it, or accept UTC input) or drop it from the schema so the data model doesn't carry a field that does nothing.

Nothing in code, tests, or style checks is broken — this list is about tightening error handling, test coverage, and doc accuracy rather than fixing defects.

# tidewick

A small, dependency-free Python library and command-line tool that predicts tide heights for a handful of
fictional stations from harmonic constituents stored as JSON. It exists as example material: the stations,
the numbers and the project are made up.

## Quick start

```bash
python -m tidewick stations                 # list the stations in the data directory
python -m tidewick predict port-avery --hours 24
python -m tidewick predict cape-mallow --at 2026-03-01T06:00
```

Python 3.11 or later. No third-party packages, by policy (see CONTRIBUTING.md).

## Layout

- `tidewick/`: the package. `predict.py` does the arithmetic, `stations.py` loads station files,
  `harmonics.py` holds the constituent speeds, `cli.py` is the command line, `config.py` finds the data.
- `data/`: `stations.json` and one constituents file per station.
- `tests/`: the unit tests. Run them with `make test`.
- `tools/`: `check_style.py` (the style rules `make check` enforces) and `make_fixtures.py` (writes a
  constituents file for a new station).
- `docs/`: `ARCHITECTURE.md` and the decision records under `docs/adr/`.

## Data directory

The tool reads station data from the directory named in `TIDEWICK_DATA_DIR`, or `./data` when that is not
set.
# Contributing to tidewick

- Python 3.11 is the floor. No third-party dependencies, in the package or the tests: the standard library only.
- Keep changes small: one concern per change, with a test.
- Commit messages use the conventional form: `feat(cli): ...`, `fix(predict): ...`, `docs: ...`.
- Run `make check` before you send a change. It runs the tests and `tools/check_style.py`, which enforces:
  lines of at most 100 characters, no `print()` in the package outside `cli.py`, and a module docstring in
  every file under `tidewick/`.
- Station ids are lowercase kebab-case (`port-avery`), and they are the file names under
  `data/constituents/`.
- Releases: update `CHANGELOG.md` (newest first, one "## x.y.z - YYYY-MM-DD" heading per release), set
  `__version__` in `tidewick/__init__.py`, and tag `vX.Y.Z`.
- `tidewick/legacy_parser.py` reads the retired 0.x text format. It is frozen: do not extend it, and do not
  make new code depend on it. It will be deleted once the last 0.x data files are converted.

import os

from datetime import datetime

from tidewick import predict, stations


class PredictTest(unittest.TestCase):
    def test_height_is_near_mean_level_on_average(self):
        s = stations.load("port-avery")
        points = predict.series(s, datetime(2026, 3, 1), hours=48, step_minutes=30)
        mean = sum(h for _, h in points) / len(points)
        self.assertAlmostEqual(mean, s.mean_level_m, delta=0.15)

    def test_series_rejects_zero_hours(self):
        s = stations.load("cape-mallow")
        with self.assertRaises(ValueError):
            predict.series(s, datetime(2026, 3, 1), hours=0)

    @unittest.skipUnless(os.environ.get("TIDEWICK_SLOW") == "1", "set TIDEWICK_SLOW=1 to run")
    def test_year_long_series_has_two_tides_a_day(self):
        s = stations.load("port-avery")
        points = predict.series(s, datetime(2026, 1, 1), hours=24 * 365, step_minutes=20)
        highs = sum(
            1 for i in range(1, len(points) - 1) if points[i - 1][1] < points[i][1] > points[i + 1][1]
        )
        self.assertTrue(680 < highs < 720, highs)

**What the docs say:** README says "Run them with `make test`", and the `Makefile` defines:
```makefile

	cd tests && python -m unittest discover -s . -t ..
```

**Running it as documented:**
```bash
cd /work/tidewick && make test
```
This **fails** — 6 errors, all `FileNotFoundError: ... tests/data/stations.json`.

**Root cause:** `tidewick/config.py`'s `data_dir()` resolves the data directory as `Path.cwd() / "data"` when `TIDEWICK_DATA_DIR` isn't set. The Makefile's `test` target does `cd tests && ...`, which changes the real process working directory to `tests/`. Since there's no `tests/data/` (station data only lives in the top-level `data/`), every test that loads station data blows up. This is a bug in the `Makefile`/`config.py` interaction, not in the test logic itself — the tests pass fine once the working directory or `TIDEWICK_DATA_DIR` points at the real data.

**Fix without editing any repo file** — don't `cd` into `tests`; invoke discovery from the repo root instead (the process cwd then stays at `/work/tidewick`, so `./data` resolves correctly):

```bash
cd /work/tidewick && python -m unittest discover -s tests -t .
```
Result: `Ran 8 tests in 0.003s — OK (skipped=1)` (the one skip is the optional slow year-long test, gated by `TIDEWICK_SLOW=1`, which is expected/documented behavior).
